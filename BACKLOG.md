# Бэклог

## [OPT-001] Ускорить замену АР-панелей на КР

**Команда:** `KrPanelWindowConfiguration` → кнопка "Заменить АР кассеты на КР"
**Файл:** `CWPanelsCustomizer/KrPanelWindowConfiguration.cs`, метод `ReplaceArCurtainPanelsWithKrPanels` (~стр. 217)
**Приоритет:** средний (продакшн-запуск один раз, повторный — уже 1.3с)

### Суть
При первом запуске на АР-модели: 1048 панелей × ~300ms = **~315 секунд**.
Каждая панель — `Wall`-объект, меняется через `element.ChangeTypeId(krTypeId)` (Wall → FamilyInstance).
Revit регенерирует витражный грид внутри каждого вызова — это C++ движок, не обходится через .NET API.

### Что уже проверено (не помогло)
| Подход | Результат |
|--------|-----------|
| Явный `doc.Regenerate()` каждые 100 панелей | 0–2ms (no-op, ChangeTypeId уже регенерирует сам) |
| Отдельная транзакция на каждый витраж | +16с (хуже) |

### Данные модели
- Всего AR-панелей: **1048** (все `Type=Wall`, не FamilyInstance)
- Уникальных WallType: **4** (804 + 128 + 104 + 12 экземпляров)
- 1036 из 1048 панелей **не нашлись** через `CurtainGrid.GetPanelIds()` — вероятно, в `CurtainSystem`

### Идеи для следующей попытки

**1. Найти родительский CurtainSystem**
1036 панелей не найдены в `CurtainWall.CurtainGrid`. Добавить перебор:
```csharp
new FilteredElementCollector(doc).OfClass(typeof(CurtainSystem))
```
Выяснить структуру — может открыть новые подходы к батчингу.

**2. Батч-удаление + авторефил**
- Задать дефолтный тип панели витража = KR (`CURTAIN_WALL_PANEL_TYPE_PARAM` или аналог)
- Удалить все AR-панели одним вызовом `doc.Delete(arPanelIds)`
- Гипотеза: Revit автозаполнит слоты дефолтным типом → 1 операция вместо 1048
- Риск: слоты могут стать "пустыми", не KR

**3. Изменить WallType напрямую**
Всего 3 уникальных AR WallType. Если изменить их CompoundStructure/параметры так,
чтобы экземпляры визуально и функционально стали KR — 3 операции вместо 1048.
Риск: name clash с существующим KR WallType; нужна стратегия rename/merge.

**4. IFailuresPreprocessor на транзакцию**
Подавить внутренние проверки Revit — возможно снизит per-call overhead на 5–10%.
